**验证结论：消费者布局在实际 GPU 指令链上正确，但本轮没有观察到它相对优化后普通布局的性能优势。** 可以保留为布局实现方式；当前证据不支持把这次列顺序调整作为论文的主加速机制。

执行时间：2026-09-08。运行设备：RTX PRO 6000 Blackwell Server Edition，GPU2，CUDA 13.1。目标 GPU 在执行前为空闲状态，运行期间由原有 GPU2 文件锁协调；完成后释放，显存恢复至 14 MiB。本实验没有停止或修改其他 GPU 上的任务。

**本轮真正执行的范围。** 输入是标准按行存储的位图、带符号权重 W 和 FP16 特征 X。原生程序计算 Q[r,z]=any(Pleft[r] AND Pright[z])，形成 C=Q⊙W，再计算 Y=CX。一个 tile 是 16×32 的 C，运行时动态选取 2:4 元素、汇集元数据并发出 sparse MMA；超过两个非零的四列组保留第二平面。所有路径使用同一输入和数学操作。

这是前向加权谓词消费者的合成算子实验。W 是明确提供的输入，没有声称免费完成 TNCN 的 S 生成。它不覆盖真实时间采样、完整七通道系数构造、原生反向或模型训练；特征采用 FP16，不证明任意 FP32 训练可无损替换。

| 路径 | 实现 |
|---|---|
| natural_sparse | 连续 BMMA 列顺序；先压缩布尔结果，再交换；动态稀疏编码和消费 |
| aligned_sparse | 按 SparseTC 消费者安排 BMMA 列顺序；候选布尔值在线程内组合；其余处理相同 |
| natural_dense | 相同 B1 拓扑计算，使用布局天然匹配的普通 dense MMA 消费 |
| simt_sparse | 普通逐字位运算，允许找到首个交集后提前退出；同样的稀疏消费 |
| aligned_split | 同样的消费者列顺序，先写出 C，再用第二个 kernel 读取、编码和消费；用于归因中间物化成本 |

**正确性已经从 CPU 位置模型推进到 GPU 执行。** V1 的 30 组小样通过。V2 在五条路径上完成 350 组对照，包含每个四列组的全部 16 种局部支持模式、空图、密集支持、单一尾部 witness、K 边界、负权/零权、单位矩阵特征、特征尾部，以及 40 组新分配和交替 stream 检查。

所有 GPU 输入和实际 Q/Y 输出均已保存。独立 NumPy 程序从位图重建 Q，再以 FP64 计算 C@X，复核结果如下。

| 检查 | 结果 |
|---|---:|
| 原生主对照 | 350 / 350 通过 |
| 独立拓扑结果 | 2,590,720 个元素，全部一致 |
| 独立输出结果 | 2,510,288 个元素，全部一致 |
| 输出最大绝对误差 | 0，限本次小整数权重和二进制小数特征 |
| 位图 K 尾部 | 填充位全部为零 |
| Compute Sanitizer | memcheck、racecheck、initcheck、synccheck 全部通过；每类运行 30 组小样 |

独立原始数据复核见 [independent.json](./output/full_v2/independent.json)。这些计数是验证元素/配置数，不是独立模型训练试验数。

**完整算子计时没有显示额外布局收益。** 固定测试矩阵为 K={128,512}、特征维度={8,32,100}、tile 数={32,256,2048}，并包含每四列恰好两个支持位置与全支持两种拓扑，共 36 个形状。每个形状测量两种范围，形成 72 个结果单元；每单元五条路径、七轮随机顺序，每轮计时 20 次调用，共 2,520 个 CUDA event 区间。

“位图已准备”包括标准位图装载、列选择、拓扑计算、W 读取、系数构造、动态稀疏选择/元数据、X 读取、MMA、结果写回和 kernel launch。“每次重打包”再额外包含 GPU 从 byte 输入重建位图。两者均不包含分配和 H2D，不能当作完整训练耗时。

下表为各形状中位耗时比的几何平均。**比值=对照耗时/消费者布局耗时；大于 1 才代表消费者布局更快。**

| 对照 | 位图已准备，36 个形状 | 每次重打包，36 个形状 |
|---|---:|---:|
| 优化后的普通布局 natural_sparse | 0.9997× | 1.0000× |
| 普通 Tensor Core natural_dense | 0.9130× | 0.9551× |
| 普通位运算 simt_sparse | 1.2226× | 1.1062× |
| 显式物化 aligned_split | 1.4538× | 1.1950× |
| 每形状最快独立对照 | 0.8874× | 0.9469× |

因此，相对自然列顺序基本持平；位图已准备时，相对 dense TC 的耗时约高 9.5%，相对每形状最快独立路径约高 12.7%。相对显式物化的优势支持融合的价值，不能归因于这次列布局调整。

位图已准备时，消费者布局在 36/36 个形状上都未快于 dense TC；加入重打包后，5 个形状出现极小领先，最大约 0.18%。相对自然布局，全部 72 个结果单元都未出现超过 5% 的领先。5% 在这里仅是展示幅度的描述，不是事后修改正确性或论文验收门槛。

本次只做了一个设备会话中的七轮测量，报告描述性中位数和逐轮结果，不以此给出跨会话置信区间。所有形状均保留在 [benchmark_summary.csv](./output/full_v2/benchmark_summary.csv)，逐轮原始计时见 [benchmark.stdout](./output/full_v2/benchmark.stdout)。

**指令证据解释了“位置对齐了，为什么仍没有更快”。** V2 的消费者布局和普通布局都使用 56 个寄存器；二者编译结果均为零栈空间、零 spill，并且不含 LDL/STL。消费者布局减少了一部分交换指令，但稀疏选择、元数据汇集、加权输入和后续消费的成本仍在。

对照经过了布尔压缩：它搬运少量布尔包，实际代价远小于先前 CPU 位置模型中“384 个候选值跨线程”的直观印象。那个数字始终是位置数，不能读作 384 次 shuffle。

本机 V2 SASS 中，natural_sparse 有 22 条静态 SHFL.IDX，aligned_sparse 有 6 条；两者都有 8 条 SHFL.BFLY 和原生 HMMA.SP.16832.F32。静态指令数量包含编译器展开及控制流，不等于动态执行量或时延。这说明减少传递确实发生，但在所测算子里没有形成可见的完整收益。dense 消费者仅使用 48 个寄存器，并省去动态结构稀疏编码的这一组处理。

V1 曾因四元素数组的动态索引生成 64-byte local stack。测速前，V2 对所有稀疏路径统一改成展开选择，消除了该问题。V1 代码和小样保留，主计时全部使用 V2，未通过给基线保留这项低效来制造收益。

**硬件边界很重要。** 实测 Blackwell 上的 B1 PTX 生成 IMMA.16832.U8.U8，消费者生成 HMMA.SP.16832.F32。因此这是“B1 的 IMMA 展开路径＋原生 SparseTC”的实测，不能标成原生 BMMA 性能。相同 V2 源码的 sm80/sm89 静态编译包含 BMMA.168128.AND.POPC，但本轮没有在那些目标上运行。

已配置的两台 A800 SSH 超时；未把 Blackwell 的性能结果推广为 A100/A800 的不可能性结论。编译器还对传统 `.sp` 提示未来架构上的性能风险；本轮自然/消费者布局采用完全相同的 `.sp` 形式，没有将结果包装成所有稀疏编码和所有架构的最优性能上界。

**对后续研究的建议。** 这次列顺序可以作为已验证的前向实现细节保留；在当前设备与算子范围内，停止把它单独当作加速贡献推进。若取得原生 BMMA 设备，可以用同一合同补一次目标设备测试。要继续论文主线，应找到真实 TNCN 里尚未消除的加权结果交付或反向成本，而不是重复只看候选值位置的计数实验。
