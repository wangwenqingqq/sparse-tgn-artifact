# Paid event-index message-store prototype

Frozen before the first GPU run, 2026-09-09. Follow the qualified direct-CSR, batched-store path on GPU3 of pro6000-8, an NVIDIA RTX PRO 6000 Blackwell Server Edition. Batch sizes 32 and 200 are workload parameters.

Compare `batch_store` with one `event_index` prototype on the same 12 Wikipedia/CollegeMsg checkpoints and eight continuous steps per window. No no-grad change, cached predictions, future-read tape, Tensor Core change, precision relaxation, or learned-operation reordering. The source `_compute_msg` tail, including time encoding and current memory gathers, stays literal. Sorting preserves the original GPU sort order, including ties.

The prototype stores pending event IDs per node on the CPU. A read pays for the selected node IDs moving to the CPU, NumPy index concatenation, H2D index transfer and four gathers from the existing immutable GPU input data. A write pays the original GPU source sort, permutation D2H transfer, CPU grouping and replacement of per-node index slices. The current input row offset is passed by the step wrapper inside the timer. No reads or writes in the measured steps may be precomputed or omitted.

One-time CPU input mirrors and import of the legacy checkpoint representation are outside steady-step timing and reported separately. Initial IDs must identify events strictly preceding the checkpoint, with all four stored fields exactly matching. This is an offline immutable-event-data adapter, not a generic implementation for arbitrary dynamically generated raw messages. Input tables are already resident in the baseline; additional CPU data and index storage are disclosed. Checkpoint/RNG restore, warmup and GC are outside timing in both arms.

Before timing, require both arms to pass all 96 steps byte for byte: 119 expanded fields against the prior direct archive, including logical message stores and CPU/CUDA RNG; the original 107 fields against source. Archive complete checks and the candidate's 384 real read prefixes with node IDs and event IDs. An independent CPU/NumPy audit must reconstruct prefixes from checkpoint/prior logical stores and independently gather all fields from original data at the recorded event IDs. Failures remain archived; no tolerance relaxation or selective windows.

Use nine randomized paired rounds per window, eight complete steps per interval (216 intervals, 1728 timed steps). Primary metric is the geometric mean across all 12 medians of paired baseline/candidate CUDA timeline ratios; also report wall time, every window, both batch-size groups, and 20,000-sample descriptive bootstrap intervals for individual and aggregate ratios. The predeclared overall target is >=1.10. A smaller positive result is reported as such, and does not justify a claim of another 10% improvement. No multiplication with earlier gains.

Separate event-phase profiles must finish with 115 persistent fields byte-identical. They describe where work moved and do not replace uninstrumented timing. Include initialization time, candidate index storage, and actual prefix/write costs. No additional prototype tuning after viewing timing results in this experiment.
