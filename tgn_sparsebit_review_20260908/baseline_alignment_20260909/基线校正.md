代码差异直接影响优化是否能迁移。在该 FlashTGN 拷贝的 [state.py](sources/flash_tgn/state.py) 中，`TemporalState` 使用 GPU 上的 `mem_data`、`mail_data` 和时间戳表。`store_raw_messages` 在写入时将节点 memory 值与边特征拼成 mailbox 内容；这包含当时的动态 memory 值。TNCN 原型则仅以事件编号取回固定原始字段，随后在读取时查询当前 memory。不能仅凭原始事件编号，假定能恢复 FlashTGN 写入时的动态 memory 内容，也不能未经语义核验替换它。

该拷贝的 [lse.py](sources/flash_tgn/lse.py) 已实现 `fused_lse_gather` 调用，并有 PyTorch 回退；[layers.py](sources/flash_tgn/layers.py) 有融合 gather/encode 路径。因此下一次测量需要确认实际走到的算子路径，不能仅凭存在融合代码就认定基线启用了它。TNCN 的逐节点字典与多张量拼接开销，不能直接作为 FlashTGN 的瓶颈证据。

研究优先级随之调整：先固定 FlashTGN 工程版本、配置和实际算子路径，对齐数据划分、采样、负样本、模型与质量要求，明确预计算和在线训练的计时边界，然后从它的真实训练入口测量瓶颈与剩余优化空间。只有在 FlashTGN 路径上验证的改动，才能报告相对该基线的收益。若引入 TNCN 模型或 decoder，必须单独处理模型变化与质量可比性，不能当作同模型实现替换。

原先“优先继续 TNCN 事件索引原型的长程训练验收”的建议暂停。该原型可保留为内部机制证据；它对 FlashTGN 的价值，以及 Tensor Core 能否在 FlashTGN 之上增加收益，均待独立验证。
