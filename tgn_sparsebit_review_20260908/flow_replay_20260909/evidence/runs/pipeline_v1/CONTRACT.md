# Frozen-teacher historical replay experiment

This experiment tests an approximate replacement for a sequence of inference-time TGN memory updates. It is not a replacement for training, and is not subject to the earlier bitwise model-state acceptance criterion. Discrete state (timestamps, message caches, neighbor caches) must remain exact.

Predeclared protocol (before candidate results):

- The two existing 20,000-event chronological archives: Wikipedia and CollegeMsg. Events 0:12000 train the teacher and students, 12000:16000 select checkpoints, 16000:20000 are held out. No randomly mixed temporal windows. Features/scales fit on training data only.
- Train one TNCN mode-2 teacher per dataset for five epochs, batch size 32, using the existing source-qualified direct-CSR decoder and batched message writes. Select epoch by validation AP. Freeze all parameters. Rebuild state from zero with the frozen teacher; historical checkpoints with changing parameters are not state targets.
- Teacher replay uses 32-event updates. Replace blocks of 128 or 512 historical events (4 or 16 updates). Discard incomplete blocks at split boundaries. Predictions are made only after a replay block, on the next 32 unseen events. Intermediate predictions are outside this historical-catch-up task.
- Shared student input: initial node memory; four chronological bins of observed event features, initial peer memory, time features and direction; event counts; last event features. This is a lossy encoder, so conclusions apply to this concrete encoder. All encoder work is paid during timing.
- Matched networks: two 256-unit SiLU hidden layers and a 100-dimensional output. Both receive the same conditioning and 101 auxiliary inputs. MLP uses zeros there. Conditional FM uses interpolated normalized state residual and interpolation time. This is paired deterministic flow distillation: z_0=0, z_1=(m_end-m_start)/scale, z_s=s*z_1, target velocity=z_1. It is not Gaussian-noise generation. Euler inference uses 1, 2, or 4 evaluations.
- Three student seeds; each objective gets 1,500 Adam steps, batch size 512, learning rate 0.001. Every 100 steps evaluate validation endpoint MSE; MLP uses one evaluation, FM uses two. Keep the validation-selected checkpoint. No test-based tuning.
- Controls: exact teacher with the already-optimized batched cache writes; unchanged memory; one coarse GRU update after consuming the block's exact message metadata. The latter controls for simple update coarsening without learning.
- Student/controls retain every original 32-event message-store update and neighbor insertion; only numerical memory recomputation is replaced. Thus no hypothetical cache savings are credited. Last timestamps are updated exactly from observed events.
- Evaluate isolated block error from exact teacher starts, then closed-loop replay across the held-out suffix from the same exact state at event 16000. Save boundary query logits/labels, per-block drift, discrete-state checks and selected raw memory snapshots. Candidates use their own predicted memory to build later inputs.
- Measure seven randomized paired full-suffix replay rounds with synchronization; no teacher memory targets or encoder precomputation inside candidates. State restoration, parameter load, validation and logging outside timing. Include encoder, normalization, all flow steps, stores, neighbor insertion and memory/timestamp writeback. Separately report teacher training, target-generation, student-training and end-to-end evaluation time.
- Practical screen: full replay >=1.10x faster than optimized teacher, AP and ROC-AUC each lose <=0.01 absolute on boundary queries. These are exploratory thresholds, not a significance guarantee; report each seed and bootstrap over boundary blocks. Also compare FM directly with matched MLP and coarse GRU. No training-acceleration claim follows from replay speed.

Hardware: select an idle GPU on pro6000-8 under the existing per-GPU lock. Use deterministic FP32 with TF32 disabled, one CPU math thread, CUBLAS workspace :4096:8. Stop on another compute process appearing on that GPU. Keep attempts, raw results and actual code hashes.

References: [Flow Matching](https://arxiv.org/abs/2210.02747), [paired deterministic mappings](https://papers.neurips.cc/paper_files/paper/2024/file/6eee1da520ac78c56f3a3e0353a5da34-Paper-Conference.pdf). The conditional endpoint learner proposed here is an experimental adaptation, not an established TGN acceleration method from either paper.
